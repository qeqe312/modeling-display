# 示例参照与换题指南

本指南让实现者沿用已验证的页面，按题目替换模型，而不是凭文字重新猜一套界面。默认规范可按题目微调；用户明确指定的设计优先，但数学、直接拖动、离线与验收要求仍适用。

## 阅读顺序与参考选择

1. `SKILL.md`：输入、交付边界和必须达到的效果。
2. `references/page-spec.md`：组件树、布局尺寸、设置顺序。
3. 最近示例的 `REFERENCE.md`：原题、数学结果、默认状态、修改位置、截图和验证入口。
4. 该例的 `开发资料/源码/layout.html`、`style.css`，再读下面对应的 JS。
5. 二维读 `references/plane-geometry.md`，三维读 `references/implementation.md`；交付前按 `verification.md` 查适用关卡。

| 新题 | 首选参考 | JS 源文件 |
|---|---|---|
| 固定顶点、外接球、固定辅助线面 | [外接球导读](../examples/外接球题建模示例/REFERENCE.md) | `app.js` |
| 单点沿棱运动、随参数改变的辅助图形与读数 | [正四棱台导读](../examples/正四棱台2023真题演示/REFERENCE.md) | `model.js` 后接 `engine.js` |
| 正四面体、内外接球共心、面相切、相对棱夹角与多项判断 | [正四面体导读](../examples/正四面体内外接球与对棱夹角/REFERENCE.md) | `model.js` 后接 `engine.js`，固定模型 |
| 沿折痕翻折、圆弧动点、从属中点与播放 | [菱形翻折导读](../examples/菱形沿AM翻折与动点/REFERENCE.md) | `model.js` 后接 `engine.js`，一个旋转参数 |
| 纯二维解析几何、动圆、切线、交点与轨迹 | [椭圆二维导读](../examples/椭圆动圆切线与定距离（二维）/REFERENCE.md) | `app.js`，Canvas 2D，平移缩放 |

二维题另读 [二维实现与复用](plane-geometry.md)。它复用页面结构、标签、抽屉与按需渲染，使用等单位平面变换和约束反解；构建参考该例自己的 `build_demo.py`，不经过三维依赖打包。以下球坐标、Three.js 组装与打包步骤仅用于空间三维题。

棱台的 `model.js` 打开 IIFE，`engine.js` 关闭同一个 IIFE。必须按此顺序拼成**同一个 script**；不能当作两个独立模块加载。该例 `app.js` 是构建生成的合并结果，优先改两份原始文件。

正四面体例也按 `model.js → engine.js` 合为同一个 script，但没有动点。其 `build_demo.py` 只生成默认单文件成品；保留了两球面、四个切点、两组平移方向以及各自图层的验证入口。

翻折例也按 `model.js → engine.js` 组装。沿固定轴旋转时重新推导圆心、圆所在平面、旋转半径和合法角度；圆弧拖动用世界射线交圆平面后恢复角度，侧对观察者的退化投影采用连续分支处理。中点等从属对象由同一参数派生，不能放任它脱离题意轨迹。播放/暂停与角度滑条放在显示设置，只有用户启动播放时维持动画帧；暂停、页面隐藏和抓点后恢复按需渲染。

三个示例采用相同的球坐标相机操作、旋转灵敏度与仰角限制，后续空间三维建模默认沿用。换题时重新选择默认摆放与观察角度：优先题目底面为底，没有明确底面时优先一个顶点朝下，尽量避免以棱为底；不要照抄另一题的默认角度、尺度或坐标原点。具体要求见 [相机与默认朝向](page-spec.md#7-相机操作与默认朝向)。

## 最小换题路径

在工作目录复制所选例的上述源码文件。逐项完成下面的替换清单，再组装成工作 HTML。源码副本、工作 HTML 与最终成品应分开存放；不要直接修改内联成品中压缩的 Three.js。

| 区域 | 按新题替换 | 默认保留 |
|---|---|---|
| 题目与讲解 | 题名、来源、原题、各问推导、精确答案、坐标说明 | 两 tab、全部推导展开、滚动阅读、答案卡样式 |
| 公式概览 | 每张卡的名称、公式、目标 `data-proof` | 定位推导且保留显示状态的行为 |
| 几何数据 | 教学坐标、渲染变换、点/曲线/棱/面、主体范围 | 缓存方法、图层、对应维度视图与标签机制 |
| 设置 | 图层名称、checkbox/state/group 对应、初始开关、透明度对象 | 组件顺序、字号、多选、清空、画面精细度 |
| 实时信息 | 读数定义、单位、结果、未定义条件 | 浮层位置与读数更新机制 |
| 动点（如有） | 参数范围、轨迹、反解、依赖对象、快捷位置与滑条文字 | 单一更新入口、视图锁定、指针归属、双向同步 |
| 标签与选点 | 名称、教学坐标、特殊点优先级 | 胶囊视觉、尺寸缓存、实际矩形命中和避让 |
| 测试 | 独立数学、端点、默认位置、语义检查 | 断网加载、可信输入、抽屉、缓存与静止检查的方法 |

先列出每个控件的 `DOM ID → state key → 绘制路径或 scene group/material`。删除旧题图层时要同时删除映射与监听；新增图层时三处都要补齐。`P`、`t∈[0,1]`、固定垂足 F、球半径、四张推导卡和体积比公式均不是通用题目数据。

推导数量改变时，同步 `proof-N`、`data-lesson`、`data-proof`、定位函数边界与相关键盘处理。当前默认四张概览卡；较长推导可以合并成四个摘要，也可以调整数量并重新验证栅格，不能让某张卡指向不存在的推导。

## 组装与打包命令

纯二维题先运行其示例构建入口：

```bash
python "examples/椭圆动圆切线与定距离（二维）/开发资料/build_demo.py"
```

换题时改为读取新题自己的布局、CSS 与 JS。该入口生成无外部依赖的 Canvas 单文件，默认成品目录只有 HTML、说明、项目许可证。下面命令针对 Three.js 三维页面。

以下命令从仓库根目录运行。`python` 表示使用者当前激活环境的 Python 3.10+；若宿主要求绝对解释器路径，由使用者替换命令前缀，不写维护者电脑路径。

固定点源码放在 `work/source/` 后：

```bash
python scripts/assemble_demo.py --source-dir work/source --title "新题名称" --output "work/新题名称.html"
python scripts/package_demo.py "work/新题名称.html" --output "geo3d/新题名称" --inline
```

单动点例的两份 JS 必须显式排序：

```bash
python scripts/assemble_demo.py --source-dir work/source --title "新题名称" --script model.js --script engine.js --output "work/新题名称.html"
python scripts/package_demo.py "work/新题名称.html" --output "geo3d/新题名称" --inline
```

组装器读取 `layout.html`、`style.css` 和所列 JS，保留本地依赖标记、转义 `<title>`，不改变源码。工作 HTML 必须位于源码目录外；**它只是中间产物，尚未内嵌依赖**。打包器校验源码安全边界和固定库 SHA-256，输出可独立离线打开的 HTML 及许可证。输出目录有不同内容时打包器会拒绝覆盖，使用新的输出目录或先核对差异。

随后写简短使用说明：题目与结果、拖动/视角/设置操作、已知退化和实际验证范围。普通题目默认成品目录只包含 HTML、使用说明、项目与 Three.js 许可证，不包含工作源码、截图、日志和 ZIP。双文件版按需使用不带 `--inline` 的打包命令。

各例的 `开发资料/build_demo.py` 用于维护自身，依赖 `examples/<题名>/开发资料/` 层级及仓库公共工具。外接球与正四棱台生成已有单双文件版，其余三例只生成单文件。**不要把维护脚本原样复制到任意工作目录使用。** 普通三维新题使用上述通用组装器和打包器；二维改编 Canvas 构建外壳，并调整新题自己的路径、题名和许可证来源。

`--title` 只更新文档 `<title>`；源码里的 h1、页内题名和题目文字仍须主动替换。打包器保留工作 HTML 文件名，因此工作文件直接命名为题名，不使用 `page.html` 作为交付名称。三维示例维护构建器会写回自身合并源码或工作 HTML；需要隔离复现时复制源码并用通用组装器。外接球、棱台与正四面体脚本接受输出目录位置参数；菱形脚本固定维护自身成品；二维脚本使用 `--output` 且只写成品。按各例说明使用。

## 怎样使 example 足够可参照

每个长期示例必须具备以下材料，README 索引应能直接进入：

| 材料 | 应回答的问题 | 不合格情形 |
|---|---|---|
| 离线成品 | 最终效果究竟是什么？ | 只有源码或联网预览 |
| `REFERENCE.md` | 哪类题该用它？默认状态是什么？哪些位置需改？ | 只有题目答案，没有实现导读 |
| 可读源码 | 布局、样式、题目模型、交互如何对应？ | 只有压缩 JS 或嵌入库的大 HTML |
| 原题与题意记录 | 条件、图示、幂次和补充约定是否准确？ | 只有最终模型，无法核对题目；历史缺失原图时不编造截图 |
| 相对路径构建入口 | 能否从克隆仓库重建？ | 依赖维护者路径或已删除版本 |
| 截图 | 桌面、平板横竖屏、模型/讲解/设置各怎样排布？ | 只有一张电脑模型图 |
| 独立数学与交互脚本 | 什么被测试、如何重复？ | 用页面自己的结果作唯一数学证明 |
| 报告 | 对应哪份成品、环境、测量方法、失败/未测项是什么？ | 只写“全部通过”，成品改后沿用旧报告，声称模拟等同实机 |

截图用于布局参照，不当作逐像素比较标准：不同系统字体可有细微差异，但组件顺序、断点行为、卡片宽高关系、颜色语义和控件位置应一致。共享视觉改动后，重建示例并更新受影响截图；数学或手势改动后，同时更新对应验证记录。

## 换题完成前的自查

普通题目验证完成后清理本次创建的临时源码、工作 HTML 和验证资料，仅保留默认成品；不要将临时目录作为长期示例归档。指定为 skill 示例时才保留可复现开发材料。

- 原题所有条件和每问解答都替换了，没有原例的答案、标签、读数或选择坐标残留。
- 新题的模型中心/半径、fit 和缩放范围重新计算，初始模型在公式区之上完整可见。
- 设置映射均作用于对应模型；定位公式不改变用户设置。
- 动点入口、合法轨迹、端点退化及滑条与直接拖动同步符合新题，不照搬旧轨迹反解。
- 对最终成品完成 [验收矩阵](verification.md)，按实际范围报告结果；不能以读完源码替代执行测试。
