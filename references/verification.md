# 验证与判定标准

每个新题需要独立数学验证、实际浏览器输入验证和视觉复核。旧示例已通过不证明新题正确；组件“存在”不等于可以操作。测试与截图针对最终打包文件，不能只检查旧源码副本。

## 环境与命令

需要 Python3.10+、Node.js18+及Playwright。下文 `python` 表示当前已激活环境的解释器；可替换为你自己的命令/路径，不需要维护者的Conda或GPU环境。以下维护回归命令在完整源码仓库根目录执行；部署的 skill 副本通常不含 `tests/` 和开发依赖清单。只运行示例检查时可直接安装 `python -m pip install playwright`、`python -m playwright install chromium`，再使用下面对应例的脚本。

```sh
python -m pip install -r requirements-dev.txt
python -m playwright install chromium
python -m unittest discover -s tests -p "test_*.py" -v
node tests/math.mjs
python tests/browser_check.py
```

已有浏览器可设置 `GEO3D_BROWSER`，示例检查也接受 `BROWSER_EXECUTABLE_PATH` 别名；否则使用Playwright安装的Chromium。选择的可执行文件由使用者环境提供，不在代码里固定个人路径。保持浏览器沙箱；不能通过 `--no-sandbox` 或修改主机安全配置来绕过测试环境限制。

`tests/browser_check.py` 覆盖历史通用模板的引擎/安全回归，**不代表当前示例布局已验收**。CI 执行上面的基础命令，五个当前示例各自运行开发资料中的检查：

| 示例 | 适用验收重点 | 额外入口 |
|---|---|---|
| 外接球 | 固定模型、球径与面积、完整讲解、单双文件 | `inspect_demo.py` |
| 正四棱台 | 沿棱动点、体积比、线面角、端点与相机锁定 | `inspect_demo.py` |
| 正四面体 | 两球共心、面相切、对棱方向与四项答案 | `check_rotation.py` 对照前三个三维例；`inspect_demo.py` |
| 菱形翻折 | 固定轴旋转、圆弧反解、中点、播放/暂停与退化 | `inspect_demo.py` |
| 椭圆二维 | 等单位平面、交点、实虚线、半径/轨迹拖动与视图锁定 | `inspect_demo.py`、`check_archive.py` |

例如重建外接球后：

```sh
python "examples/外接球题建模示例/开发资料/check_browser.py"
node "examples/外接球题建模示例/开发资料/check_math.mjs"
python "examples/外接球题建模示例/开发资料/inspect_demo.py"
```

其他题目替换目录名，具体命令和报告位置见[示例索引](../examples/README.md)与各例导读。先独立数学，再最终成品浏览器与截图复核；新题复制用例结构、替换独立期望值和定位关系，不能沿用原题数字或报告测试条数。

二维参考入口为 `examples/椭圆动圆切线与定距离（二维）/开发资料/` 中的 `check_math.mjs`、`check_browser.py`、`inspect_demo.py`。二维把相机测试换成平面坐标往返、平移缩放与 cx/cy/scale 锁定；用实际 Canvas 绘制路径验证线段/射线范围及实虚线分界，并观察 Path2D 分配和 idle 帧。它仍需同样的四种视口、可信输入和完整解题检查。

## 1. 数学关卡

| 检查 | 通过判据 |
|---|---|
| 题干与参数 | 所有已知条件、量名与模型一致；用长度/点积/反三角函数反算 |
| 坐标映射 | 教学坐标与渲染坐标可正反转换，选点显示与推导使用同一建系 |
| 每问答案 | 独立代码不导入页面计算函数；精确式对应的数值与实现误差≤1e-9 |
| 体积/比例 | 量的定义正确；互补部分之和等于整体；端点比值/零分母明确 |
| 动点 | 起点、中点、终点及内部采样均在约束轨迹，非法输入被限制 |
| 角与退化 | 用独立法向量/投影检查；共点/共线时承认未定义，不输出NaN |
| 屏幕反解 | 有效多视角、多缩放、平移、view offset往返误差≤1e-9；退化射线返回null，记录有效样本数 |

不预设“页面总是正确”或“测试总是正确”；失败时定位题意、公式、期望和实现。不能跳过全部困难采样后说反解通过。

## 2. 结构、外观与响应式关卡

至少检查以下视口；两个平板模式设置 `has_touch=True` 并检查 coarse 分支。它们是复现基线，真实设备验证另行说明。

| 视口 | 应出现的布局 |
|---|---|
| 1600×1000、fine | 80px页头、390px常驻面板、剩余主模型区 |
| 820×1180、coarse | 72px页头、全宽模型、底部全宽抽屉 |
| 1180×820、coarse | 72px页头、全宽模型、390px左抽屉 |
| 390×844 | 68px页头、3列紧凑读数、2×2公式概览、底部抽屉 |

分别保存模型初始状态、完整推导可读状态、显示设置状态；动点例再保存内部位置与端点/未定义状态。截图命名应标明viewport和状态，并与生成时的源码版本相对应。

逐项判断：

- 原题完整，所有 proof 卡初始 `hidden=false`；没有“下一步”才能看到答案的流程。
- tab、运动组、图层、字号/透明度、多选、精细度的顺序与页面规范一致。
- 页面不横向溢出；公式概览完整在视口内，模型及标签避开底部公式和顶部关键控件。
- 标签在默认画面、缩放与平移后可辨，字体最小/最大变化后没有幽灵命中区；三维另查正视、俯视、立体视角。
- 三维：初始、“立体”与复位画面使用同一默认朝向；优先题目底面为底，没有明确底面时优先一个顶点朝下，尽量避免最低支撑为棱。按世界竖直方向检查模型摆放，并复核坐标轴、标签与教学坐标映射。
- 二维：全图、复位与横竖屏切换后横纵等单位，主体位于预留范围；平移后直线/射线正确裁剪，线段不产生延长线，实虚线按真实边界划分。
- 文案/公式长时没有截掉关键值；卡片可滚动、控件可触及、字号和对比度可读。
- 抽屉方向正确，关闭后模型可操作，切方向收起抽屉，隐藏面板不接受键盘焦点。

可以对规定尺寸使用计算样式/矩形测量（例如390px面板、元素是否出视口）。截图比较关注组件关系、层次和清晰度；不要求字体后备不同的系统逐像素一致。

## 3. 实际输入关卡

用Playwright鼠标和浏览器可信触摸输入（Chromium可用CDP `Input.dispatchTouchEvent`）。记录 `isTrusted` 和pointerType。合成 `dispatchEvent(new PointerEvent(...))` 只能补充，不能替代浏览器输入链路。

| 操作 | 需要验证 |
|---|---|
| 点 / 点字母 | 多选累积，再点取消；空白点击保留；tap不改变视图 |
| 空白拖 / 缩放 / 平移 | 鼠标与单/双指符合映射；二维空白平移与锚点缩放，三维空白旋转、右键/Shift平移且无contextmenu；拖动阈值补齐起点位移 |
| 三维旋转与复位 | 鼠标与单指方向、0.006 rad/CSS px 灵敏度一致；仰角限制 ±1.49 rad，到边界后反向拖动立即恢复；世界竖直方向向上；复位回默认朝向，居中保留观察角度 |
| 二维映射与全图 | 不同 scale/cx/cy 下教学坐标往返正确，缩放锚点保持，DPR只影响位图；全图适配题目范围 |
| 动点、手柄与标签拖动 | 抓字母不跳点，位置沿轨迹连续变化；声明的点/圆周/手柄与标签均可用 |
| 两端与越界 | P与端点重合仍能抓回；越界限制到合法域，不误选静态顶点 |
| 双向同步 | slider/快捷按钮更新模型和读数；模型拖动同步slider与选择坐标 |
| 视图锁定 | 动点期间二维cx/cy/scale或三维cam全部字段、target与相机位置不变；滚轮、第二指不能接管 |
| 取消与释放 | pointercancel、lostcapture、失焦、旋转屏幕后清理；恢复普通视图操作 |
| 显示设置 | 每个开关作用于对应groups/label；透明度作用于声明对象，质量作用于渲染像素比 |
| 定位推导 | 图层、选择、参数、二维视图或三维cam/target在定位前后不被重置 |
| 播放（如有） | 用户启动后播放，暂停/抓点/页面隐藏后停止；与滑条、直接拖动、从属点和读数共用更新入口 |
| 键盘与焦点 | tab键、面板焦点限制、Escape关闭/清空、减少动画偏好 |

浏览器输入坐标可能被量化，拖到指定 t 的交互误差与数学/反解误差分开记录。当前棱台检查以 t 容差2×10⁻⁵适应该环境输入精度，不把这当成其它屏幕/轨迹的固定保证；新题容差应根据屏幕尺度与输入精度说明。

## 4. 性能与离线关卡

- 三维将待测图层至少显示一次、等待过渡与resize结束，再记录 `renderer.info.memory.geometries`。WebGL可能首次显示才上传缓冲，不把一次预热增加当成泄漏。
- 二维观察实际 Canvas 绘制调用及 Path2D 构造，不能只读取固定的调试计数。验证图层像素变化、路径缓存、位图精细度、裁剪与线型。
- 连续至少90次动点/视图/设置更新，拓扑不变时二维路径或三维几何数不持续增长。必要时同时检查对象分配、材质与纹理。
- 停止播放和输入并等待过渡完成后，再观察600ms，新增渲染帧应为0；页面隐藏时也不维持循环。
- 标签正常移动时不反复读取offset尺寸，不持续执行强制布局。可记录render CPU耗时、帧间隔和环境，但不能把CPU提交耗时当作GPU完成或真实设备FPS。
- 断网 `file://` 启动单文件，以及存在时的双文件版；不存在网络资源请求、控制台异常或丢失依赖。Canvas初始化或缺库/WebGL失败时显示提示。
- 正式URL不暴露 `__S`；调试用 `#geo-debug`。发布目录无运行PID、日志、临时源码或默认ZIP。

## 5. 报告与完成判定

报告至少包括：题目/版本与最终成品哈希、数值期望、独立数学结果、采样数量与容差、浏览器版本与视口、鼠标/可信触摸证据、截图路径、缓存/idle指标及未验证平台。重建后核对证据与成品一致；路径使用仓库相对位置，预览PID、日志和个人环境配置不入库。

各例报告条数随覆盖范围变化，它们说明测了什么，**条数不是新题评分标准**。已有记录不包含实体iPad/Safari，不能声称已验证这些硬件。

全部适用关卡通过才称完成。缺浏览器/设备时保留已做的工作并明确尚未验证的部分；不制造“全部通过”报告，不让测试结果仅靠匹配标题或CSS文本得出。
