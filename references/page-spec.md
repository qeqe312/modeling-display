# 二维与三维教学页面规范

同一套页面结构也用于[椭圆二维示例](../examples/椭圆动圆切线与定距离（二维）/REFERENCE.md)。二维主画面用 Canvas 2D、等单位坐标与平移缩放，左上工具为全图/放大/缩小；其余侧栏、抽屉、标签与公式定位保持一致。二维实现边界见 [plane-geometry.md](plane-geometry.md)；本文件的球坐标相机章节只适用于三维。

本文件是当前默认页面的规范化说明。设计依据包括外接球、正四棱台、正四面体、菱形翻折与椭圆二维的已认可页面。规则分为：**必须保持的结构/行为**、**默认视觉参数**、**按题目推导的参数**。用户明确要求其他设计时可调整默认视觉；不能牺牲数学、约束、离线或基本操作。

## 1. 阅读后的产出应是什么

同一份 HTML，在电脑有左侧教学面板，在平板有覆盖式抽屉；模型、实时读数和题设答案同时可见。学生打开就能读完解题，不需要先完成点击任务。页面不用构建工具、在线字体、远程公式渲染或服务器才能打开。

可复用内容：页面分区、两个 tab、卡片、显示控制、DOM 标签、对应维度的视图手势、抽屉、缓存与按需渲染。

必须重新做的内容：原题/出处、顶点坐标、几何约束、法向量/长度/体积/角度、辅助点、图层名称、默认图层、最终结论、异常状态与独立测试。

## 2. DOM 与组件边界

```text
header.app-header
  identity：小标识、英文小字、h1 题目名
  header-actions：menu、focus、reset
#app
  aside#panel
    drawer-heading：标题、close
    panel-tabs：tab-lesson、tab-settings
    panel-scroll
      lesson-panel：原题、interaction-note、lesson-list、坐标说明
      settings-panel：动点控制（可选）、图层、文字、范围控制、多选、精细度
    panel-footer：离线提示
  main#stage
    canvas#cv
    #labels
    stage-toolbar：data-view、fit
    #readout
    stage-bottom：step-caption、solution-overview、stage-meta
    #error
#scrim
```

保留共用 ID 可直接复用事件绑定。图层 ID 可按题目改，但需同时修改 HTML、`checks`/state 映射、可见性与测试。不要只改文本，留下监听不存在 ID 的代码。

| 组件 | 职责 | 不应承担 |
|---|---|---|
| lesson-panel | 完整原题、按逻辑排列的全部推导、精确与近似答案 | 解锁答案、调整用户图层 |
| settings-panel | 运动与外观控制、选择列表 | 隐藏另一部分解答 |
| #labels | 顶点/长度/注释显示与命中信息 | 覆盖画布接收全部手势 |
| #readout | 当前模型状态或静态结论，语义明确 | 将题设答案冒充任意拖动位置的值 |
| solution-overview | 关键公式摘要，点击定位 proof 卡 | 切“步骤”后重置模型 |
| engine | 平面视图或三维相机、输入、布局、标签、渲染调度 | 硬编码另一题的解法 |

`#labels` 使用 `pointer-events:none`，命中由画布读取投影点和标签矩形；无需为每个字母注册另一套触摸事件。

## 3. 布局参数与断点

以下沿用外接球与正四棱台的基础 `style.css`，其余示例继承这套布局；它们是默认值，不是与几何比例相关的数学常数。

| 部位 | 桌面默认 | 平板/窄屏默认 |
|---|---|---|
| 页头 | 80px | coarse 或 ≤1100px 为 72px；≤600px 为 68px；矮横屏为 62px |
| 面板 | >1100px 且 fine，390px 静态栏 | ≤1100px **或** coarse 时覆盖式抽屉 |
| 横屏抽屉 | 专注模式也可覆盖打开 | 左侧、宽 `min(390px,86vw)`，页头下到屏幕底部 |
| 竖屏抽屉 | — | 底部、全宽、高 `min(78dvh,890px)`、顶部圆角22px |
| 面板内边距 | 22px | 抽屉24px左右；保持独立纵向滚动 |
| 画面工具 | 主画面左上，left24/top22px；二维全图/缩放，三维快捷视角/居中 | left20/top18px，手机left14/top15px |
| 右上读数 | 外接球170px宽；棱台190px | ≤600px 时在工具栏下，3列压缩，临界提示独占一行 |
| 底部公式容器 | max-width800px，4列、gap8px | ≤600px 为2列、gap6px；全都留在视口内 |
| 公式卡 | min-height98px | 手机77px；矮横屏73px |
| 图层/标签开关行 | min-height49px，复选框21px | 整行可点击；按钮目标至少44px |
| 范围输入 | 高40px，字号14–32、默认22px | 高44px；同一范围、标签与数值同时显示 |

CSS 同一选择器可能被后面的媒体规则覆盖，以最终计算样式为准。“矮横屏”指 `orientation:landscape` 且 `max-height:700px`。不要复制前面未生效的348/326px侧栏宽度作为基线。`78vh` 应写在 `78dvh` 前作 fallback，不能反过来覆盖动态视口。

模型视口宽度由剩余空间决定，不能在平板给画布与侧栏各分一半。隐藏抽屉不改变内容存在性；portrait 与 landscape 切换时收起抽屉、清理手势。

正文长时滚动面板；不要让整个页面横向滚动。支持 `100dvh` 与安全区，保留常规 `vh` fallback，且尊重减少动画偏好与用户页面缩放。

## 4. 内容与显示设置顺序

题目与讲解：原题 → 一句解题/操作提示 → 全部 proof 卡 → 可选坐标详情。四张概览卡是默认节奏，完整推导数量按题目增减；改变数量时同步 `data-proof` 映射、ID、定位范围与键盘导航，不能强行藏答案来维持四步。

显示设置依次为：

1. 有动点时显示参数滑条、端点/关键位置按钮、当前比例与相关读数。静态题完全省略此组。
2. 图层：主体面、与解题直接相关的辅助对象、角标、坐标轴。
3. 文字：顶点字母、边长数值、字号。
4. 透明度：说明到底控制球面、主体面或某类辅助面。
5. 顶点多选：chips、教学坐标、清空。
6. 精细度：自动、省电、清晰。

不要为静态顶点造“运动”控件。不要把动点滑条放进题目 tab 或把手指直接拖点改成只有滑条。

默认图层以解法为依据：主体与必要辅助图层可见；坐标轴、额外演示对象按需打开。示例中的开关值是该题的选择，不是所有题目的通用默认。

## 5. 公式、文字与标签

主文字使用系统字体（Segoe UI、Microsoft YaHei、PingFang SC等），数学使用 Cambria Math/Georgia 类后备字体，不依赖网络字体。公式可用 Unicode、受控 HTML 上下标与分行，不要求在线 MathJax/KaTeX。

| 元素 | 默认 |
|---|---|
| h1 | 20px、600；手机15px |
| proof 标题 | 桌面15px；平板竖屏17px |
| 正文/提示 | 常规12–14px，长推导行高约1.8 |
| 顶点字母 | 22px、600、14–32px可调 |
| 边长标签 | 15px，手机13px；不跟随大号顶点膨胀 |
| 公式概览 | 约19–21px；长公式按例缩至18px，手机16–19px |

胶囊标签背景 `#161B22`、描边、2px 9px padding、8px圆角。普通亮蓝、动点亮橙、辅助点亮紫；选中为橙底深色字。尺寸缓存在字体/文本/显隐改变后更新，不在每次 pointermove 读取布局。

避让使用真实矩形，并处理投影重合与0距离；模型在正视/俯视时仍须可读。标签限制在可用视口，避开底部公式。若顶点密度太高，选择缩小或关闭边长、改善视角/布局，不能声称启发式算法对任意题都保证不重叠。

## 6. 静态答案与动态读数

外接球例的右上读数是固定结论：直径、半径、表面积。底部四张卡定位完整推导。

棱台例的右上读数是当前 t、两面夹角、sinθ；设置页另显示比例与体积比。底部结论明确标为题设状态，拖动后仍保留题设答案。t=0 时平面PBC未定义，不能显示极限值当成实际角度。

这两种读数语义允许复用，字段名/单位/临界条件需要由新题决定。保持有效位与精确答案分离，计算使用浮点原值，显示才格式化。

二维例的 r、k₁k₂、|PQ| 是当前参数读数；菱形例的角度、长度和体积也随参数同步。滑条、快捷按钮、直接拖动和播放须使用同一更新入口，未定义对象同步隐藏，不能让界面保留上一个有效位置的读数。

### 二维视图操作

Canvas 2D 使用等单位坐标，y 轴向上；鼠标/单指拖空白平移，滚轮或双指缩放，双指同时可平移。全图按该题的主体、必要辅助图形与浮层预留适配；缩放以指针或双指中点为锚点。动点拖动期间锁定 cx/cy/scale，松手或取消后恢复操作。坐标、裁剪与反解细节见 [二维实现](plane-geometry.md)。

## 7. 相机操作与默认朝向

后续空间三维建模默认沿用三个示例的球坐标环绕方式，保持世界竖直方向向上。水平拖动改变方位角，垂直拖动改变仰角；鼠标与单指灵敏度均为 0.006 rad/CSS px，仰角限制 ±1.49 rad。保留滚轮缩放、右键/Shift 平移、双指缩放和平移；除非用户另有要求，不改用轨迹球或自由翻滚。

默认朝向优先以题目中的底面为底，没有明确底面时优先选择一个顶点朝下。尽量让模型最低处是一个面或一个点，避免以一条棱为底；保持适当仰角与方位角，使模型仍有立体感、关键结构便于讲解。这里的最低处指模型在世界竖直方向上的最低支撑，不要求屏幕投影中整个底面具有相同像素高度。

初始视角、“立体”与“复位视角”使用同一默认朝向；“居中”只调整画面适配，保留用户观察角度。默认朝向要求不限制用户手动观察，不在拖动时强制吸附或复位。默认角度、距离与包围范围按新题计算，不逐字照抄示例参数。

模型换基或调整朝向时，坐标轴、辅助线、标签与教学坐标必须保持一致。桌面及平板横竖屏检查初始和复位状态，关键标签避开读数、工具栏与公式；相机实现见 [implementation.md](implementation.md)。

## 8. 可微调范围与验收边界

可微调：题目名、来源、推导数量、字段、默认视角、缩放范围、图层默认值、几何线半径、辅助透明度、长公式字号。视角和适配包围半径必须据新模型计算。

默认保持：暗色色板、两个 tab、设置组顺序、桌面与抽屉策略、胶囊标签、公式定位方式、字体层次与卡片风格。设计变更应有题目或用户要求作为理由。

不能微调掉：独立数学验证、直接约束拖点、二维视图或三维相机锁定、完整解答、真实控制功能、离线与许可证、资源缓存、按需渲染。

验收看组件相对位置、清晰度和行为，不要求字数/题目数据不同的截图逐像素相同。基准视口与判断方式见 [verification.md](verification.md)，精确 CSS 与 JS 行为参照所选示例源码。
